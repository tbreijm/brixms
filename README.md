by epistemic status, at a cost proportional to change — never to the size of the
world.**

([ADR-0002](./spec/adr/ADR-0002_SOC_Constitution.md)), derived from the

[`spec/SOC_Semantic_Laws.md`](./spec/SOC_Semantic_Laws.md).

## The constitution in one screen

BrixMS has **one category**. Its objects are *configurations*; its arrows are
*witnesses* between them. A running system, a simulation of it, the model it
implements, and the world fragment it is coupled to are not four primitive kinds
of thing — they are configurations, and the relationships between them are
witnesses. There is no schema/instance primitive: "instance-of" is the carrier
of an identity witness, and "has-type" is *one realization judgment under one
regime among many*, not a distinguished ontological relation.

Three structures sit on the one category:

- **Realization is a lax functor** `R : SOC → Rel`. Laxity is deliberate and
  one-directional — *whatever a chain realizes, the composite realizes*, so
  compressed and compiled paths are sound (the compiler direction). A **tight
  subcategory** generated by a specified class `𝒢` of primitive *logged*
  witnesses gives *exact* decomposition for every committed settlement (the
  audit direction). One axiom buys soundness everywhere; one earned subcategory
  plus one decomposition certificate buy accountability where it is owed.
- **Settlement is a coalgebra** on execution configurations `⟨world, policy,
  history⟩`. Candidates come from realization filtered by an admissibility
  judgment `Adm`; a **keyed calendar** determinizes the observed successors via
  `select_K`, committing the least-key candidate. **Deliberation is plural;
  commitment is singular.** The committed behavior functor is frozen at
  `F_O = D_O = 1 + O×X` with `O = O_min` (settlement-event tags), versioned like
  the canon vectors (ADR-0002 §8, ⟨D-FO⟩).
- **Saturation** separates *administrative* steps (`τ`) from *realizing* steps
  (`o ∈ O`) and is divergence-sensitive: it hides finite administrative prefixes
  but never identifies quiescence with an infinite administrative search.

### The epistemic outcome lattice

Every judgment carries an epistemic status. The lattice is defined once, in
[`crates/brix-semantic/src/outcome.rs`](./crates/brix-semantic/src/outcome.rs),
and frozen (ordinals are canonical ABI, append-only):

```
             Proven            Refuted     ← theorems (revision-invariant), opposite poles
                 \               /
                  \             /
                 Audited                   ← tight 𝒢-decomposition replay-verified; not a theorem
                     |
                  Derived                  ← settlement-authoritative within a revision
                     |
              Measured / Estimated         ← external certified result / simulation / estimate
                     |
                  Unknown                  ← bottom; never collapses to true/false
```

**`Unknown` never collapses.** Resource exhaustion, an unterminated search, a
replay that does not complete exactly — all fail closed to `Unknown(reason)`,
never silently to `Proven`/`Audited` or down to `Refuted`. The partial order is
an explicit function, not the enum declaration order (`Proven`/`Refuted` are
declaration-adjacent but lattice-incomparable).

**One authority per outcome** (the verifier-authority table, ADR-0002 §4.1):

| Outcome | Sole authority |
|---|---|
| `Proven` / `Refuted` | the dependent proof kernel — regimes may *construct candidates*, never assert acceptance |
| `Audited` | the audit-factorization checker (reference replayer), replaying a `Decomposition` against the log |
| `Derived` | the settlement kernel (committed coalgebra) |
| `Measured` / `Estimated` | the named external driver / simulator, via a certified-result envelope |
| `Unknown` | any regime may *emit* it; no one may *downgrade* a stronger outcome to hide a failure |

The canonical upgrade path is `Derived → Audited → Proven`: engine commit,
oracle replay, kernel elaboration — each step a **new judgement**, never a
downgrade. Differential testing *is* an outcome upgrade, not a test-only
activity.

### Two kernels, one substrate

There are exactly two trusted kernels; they share one substrate and depend on
neither each other nor the regime stack.

- **Settlement kernel** — the committed `D_O`-coalgebra `γ = select_K ∘ δ` plus
  audit factorization. Answers *which settlement the calendar committed at this
  step, and what its logged tight decomposition is*. The naive
  recompute-the-world loop is **deliberately retained** as its reference oracle;
  the fast engine is differential-tested against it.
- **Dependent proof kernel** (`brix-kernel`, forthcoming — Build Plan step S7) —
  certifies propositions *about* the configuration/witness/behavior structure.
  Answers *does this canonical explicit term prove this proposition in this exact
  context*. Depends **only** on `brix-semantic`.

The **substrate** — configurations, witnesses, regimes, decompositions, and the
epistemic artifacts (`ContextId`, `Proposition`, `Evidence`, `Judgement`,
`Dependency`, `Witness`, `RegimeId`, the generator registry `𝒢`, `Decomposition`,
`Realizes`) — lives in
[`crates/brix-semantic`](./crates/brix-semantic), content-addressed, versioned
encoders, depending only on `brix-canon`.

### The O(Δ) invariant (the anti-v1 doctrine)

> **Cost per committed step MUST be ∝ |Δ| × (index fanout), and MUST NOT be
> ∝ |world|. Doubling the number of *inert* configurations MUST NOT change
> per-step cost.** (ADR-0002 §9.1)

This is a conformance/benchmark gate, not a later optimization. Candidates are a
materialized incremental (semi-naive, delta-driven) view; the calendar is a
priority queue keyed by `K = (phase/time, priority, canonical-digest tie-break)`;
canonical digests are interned to dense `u32` handles used in the hot loop; state
is persistent HAMT-style maps with structural sharing and an O(1) chained history
digest. A change that regresses the invariant is a red build.

## Repository layout

```text
crates/
  brix-canon        canonical encoding + content identity — the trust root
  brix-semantic     the SOC substrate: outcome lattice, ContextId anchor,
                    witnesses, regimes, 𝒢, decompositions, Realizes — depends
                    only on brix-canon
  soc-core          settlement kernel: interner + persistent store + chained
                    history digest (E1); realization interface + Adm + naive
                    oracle (S2/E2); keyed calendar + commit + audit-factorization
                    checker → Audited (S3/E4); the O(Δ) gate harness
  soc-regimes       realization regimes: literal-equality slice + the structural
                    (brix.type) regime with 14/14 differential parity
  brix-conformance  fixture format, differential harness, fuzzer, corpora
                    (conformance, acceptance, structural-regime, selfhost parity)

  # legacy engine — retained ONLY as the differential oracle, slated for retirement
  brix-ast brix-ir brix-phase brix-oracle brix-rt brixc brixpkg brix-cli brix-diag

sdk/                WIT worlds + Rust guest SDK for WASM Drivers
spec/               the constitution, master plan, and language specification
docs/               SOC foundation (.tex), language spec long-form, article materials
packages/           Ring 1 BrixMS packages (brix.core, brix.type, brix.math, …)
vectors/            frozen canonical golden vectors
```

The old engine stack (`brix-ast`, `brix-ir`, `brixc`, `brix-rt`, `brix-phase`,
`reflect.rs`/`infer.rs`) is kept **only as a differential oracle** during the
transition — the structural regime is tested `ConflictKind`-for-`ConflictKind`
and `FactId`-for-`FactId` against it — then retired. Its internals are not
ported. Under SOC the `brixc`/`Ty` toolchain is demoted from the semantic center
to *one finite `F_O`-presentation frontend* among possible frontends (ADR-0002
§2; Build Plan step S6).

## Building & testing

**Prerequisites:** Rust **1.96.1**, pinned in
[`rust-toolchain.toml`](./rust-toolchain.toml) (`rustup` installs it on first
build). Nothing else is required.

```bash
git clone https://github.com/tbreijm/brixms.git
cd brixms
cargo test --workspace
```

The full CI suite ([`.github/workflows/ci.yml`](./.github/workflows/ci.yml)) runs
these gates:

| Gate | What it holds |
|---|---|
| **fmt / clippy** | `cargo fmt --all --check`; `cargo clippy --workspace --all-targets -- -D warnings` |
| **test** | `cargo test --workspace` |
| **determinism** | `HashMap`/`HashSet` clippy-denied in semantic paths; byte-identical output across repeated runs of the frozen-artifact producers |
| **conformance** | `cargo test -p brix-conformance` — the differential corpus |
| **acceptance** | the spec-derived acceptance corpus (parse/lower/check/phase + negative fixtures) |
| **reproducibility** | `cargo test -p brix-cli --test reproducibility` — the in-repo proxy for the two-machine gate |
| **cargo-deny** | dependency licensing and advisories |

Determinism is enforced mechanically, not just documented: `unsafe` is denied
workspace-wide and the toolchain is pinned. The **O(Δ) benchmark**
([`crates/soc-core/tests/o_delta_gate.rs`](./crates/soc-core/tests/o_delta_gate.rs))
is armed but `#[ignore]`d — it doubles inert configurations and asserts per-step
cost is unchanged, and goes live against the incremental engine at step 6.
